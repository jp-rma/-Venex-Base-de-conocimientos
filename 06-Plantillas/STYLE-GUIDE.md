# Guía de Estilo de la Documentación (STYLE GUIDE)

## Objetivo

Establecer un formato uniforme para toda la documentación de la Technical Knowledge Base (TKB).

La estandarización facilita la lectura, el mantenimiento y la actualización de los documentos.

---

# Tipos de documentos

| Código | Tipo |
|---------|------|
| PROC | Procedimiento |
| GUIDE | Guía Técnica |
| RMA | Caso documentado |
| CHK | Checklist |
| COMP | Compatibilidad / Incompatibilidad |

---

# Nomenclatura

Todos los documentos deberán utilizar el siguiente formato:

TIPO-NNN-Nombre-del-documento.md

Ejemplos:

PROC-001-Manipulacion-Notebooks.md

GUIDE-001-Conectores-PWM.md

RMA-001-Bajones-de-FPS.md

CHK-001-Control-Final-de-Armado.md

---

# Idioma

Toda la documentación deberá redactarse en español técnico.

Se utilizarán términos en inglés únicamente cuando formen parte de la nomenclatura del fabricante o sean de uso habitual en informática.

Ejemplos:

- BIOS
- UEFI
- SSD
- CPU
- PWM

---

# Redacción

Se recomienda utilizar:

- Oraciones claras y directas.
- Vocabulario técnico.
- Párrafos breves.
- Listas cuando mejoren la comprensión.

Evitar:

- Opiniones personales.
- Expresiones ambiguas.
- Información sin verificar.

---

# Versionado

Todo documento podrá actualizarse cuando:

- Se detecte un nuevo procedimiento.
- Cambie una tecnología.
- Se identifique una mejora.
- Se detecte un error.

---

# Objetivo de la documentación

Cada documento debe responder al menos una de estas preguntas:

- ¿Cómo realizar correctamente una tarea?
- ¿Cómo diagnosticar un problema?
- ¿Por qué ocurre una falla?
- ¿Cómo prevenir que vuelva a suceder?
- ¿Qué conocimiento puede reutilizar otro integrante del equipo?
